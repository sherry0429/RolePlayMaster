# 可运行模块化版本（全局兼容）

这个版本不是 ESModule 强隔离方案。

而是：

- 多文件模块化
- 全局兼容
- 可直接运行
- 保持原 onclick 架构
- 不破坏原项目逻辑

## 为什么这样做

你的原项目本质是：

- 单脚本
- 全局状态
- 全局函数
- inline onclick
- 大量共享变量

这类项目如果直接切 ESModule：

一定会出现：

- appData 未定义
- currentChatId 未定义
- requestLog 未定义

因为原本依赖同一作用域。

所以这里采用：

# “渐进式工程化”

即：

- 先拆文件
- 保持全局兼容
- 保证功能正常
- 后续再慢慢去全局化

这是大型旧项目最稳的重构方式。
